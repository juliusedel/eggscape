# Assumptions

Decisions made while building Eggscape without asking. Each entry says what was assumed and why, so it can be
revisited deliberately.

## Environment and tooling

- **Toolchain.** Built and tested with Xcode 27.1 (Swift 6.4, iOS 27.1 SDK) on macOS 27. The deployment target stays
  at iOS 17.0 as specified; APIs newer than iOS 17 are used only behind `#available` checks.
- **No Homebrew on the build Mac.** `brew install xcodegen` was not possible, so `scripts/bootstrap.sh` builds pinned
  versions of XcodeGen (2.46.0) and SwiftFormat (0.64.4) from source into `.tools/` (git-ignored). The Makefile
  prefers tools on `PATH`, so `brew install xcodegen swiftformat fastlane` remains the normal setup.
- **No GitHub credentials on the build Mac.** The repository could not be cloned or pushed at first, so the work
  started in a local repository whose first commit mirrored the GitHub "Initial commit". That history was later
  replayed onto GitHub's initial commit and merged into `main`.
- **fastlane is not installed on the build Mac** (system Ruby 2.6 is too old for current fastlane). The lanes are
  written and syntax-checked but could not be executed; they need `brew install fastlane` (or `bundle install`).
- **Swift 6 language mode** everywhere, with strict concurrency checking.
- **Tests** use Swift Testing for `EggscapeCore` and the app unit tests, and XCTest for the UI tests (Swift Testing has
  no UI testing support).
- **Simulator builds are unsigned** (`CODE_SIGNING_ALLOWED=NO`) in the Makefile and CI, so they work while
  `DEVELOPMENT_TEAM` is still the `<TEAM_ID>` placeholder.
- **Info.plist is maintained by hand** in `App/Info.plist` (not generated by XcodeGen), so the file is reviewable and
  the build number (`CFBundleVersion = $(CURRENT_PROJECT_VERSION)`) follows agvtool.
- **`make test`** runs the core package tests and the app unit tests as specified. The UI test (a full race) runs with
  `make test-ui` because it takes a few minutes.
- **`UIRequiresFullScreen`** is set as specified even though iPadOS 26 deprecated it; it is harmless on iPhone, and
  the app is iPhone-only (`TARGETED_DEVICE_FAMILY = 1`), so iPads run it in iPhone compatibility mode.
- **MultipeerConnectivity is deprecated in the iOS 27 SDK** ("Use Network Framework instead"). It still works and the
  spec asks for it, so Nearby play uses it, but only behind a small transport protocol so a Network framework
  implementation can replace it later without touching the lobby or race logic.

## Product direction changed by the owner (2026-10-27)

See `docs/ARCHITECTURE.md` for the full list. Consequences for the original spec:

- **§8 art direction is replaced.** Instead of a cartoon meadow with parallax layers, runner, fence and SVG vector art,
  the game shows a photo-realistic spoon and egg from directly above on a white studio background or on the live rear
  camera image. "Spoon fills the lower 40 %" became "spoon fills most of the screen", because without a landscape the
  spoon is the whole game view. Parallax layers and the runner are dropped; footsteps show up as a very subtle bob.
- **Realistic artwork is procedural** (`EggscapeArt`, pure Swift) instead of hand-made SVG: photo-real shading cannot be
  expressed well in the SVG subset that asset catalogs support, and generating eggs from data makes every shop skin
  cheap to add. UI icons are SF Symbols. Any procedural image can be replaced by a real photo (PNG) later.
- **The owner's reference photo of a brown egg is not committed**, because its license is unknown. It was only used
  to judge realism.
- **Global leaderboards and in-app purchases are now in scope** (out of scope in the original spec): Game Center
  leaderboards, and consumable coin packs via StoreKit 2. Skins are bought with coins, which are earned by playing or
  bought as packs. Coins and skins are stored locally (no cloud save, as in the original spec), so they are lost when
  the app is deleted; consumable purchases cannot be restored by design.
- **Navigation** is a tab bar (Einzelspieler, Mehrspieler, Bestenliste, Shop) instead of the start screen with
  Spielen / Mehrspieler / Einstellungen / Anleitung. Settings and the tutorial open from a toolbar button.
- **Camera mode** needs `NSCameraUsageDescription`. The camera image is only shown on screen, never recorded, stored
  or sent, so the privacy label stays "Data Not Collected". The prompt appears only when the player turns on camera
  mode.

## Later decisions

- **Art tournament.** Three agents built competing procedural renderers. All three eggs matched the reference photo
  closely; candidate A (physically based: exact surface of revolution, analytic studio lighting) won because its skin
  system was complete. The spoon, the broken egg and the weather effects were finished afterwards on top of it.
- **App icon** is rendered from the same spoon and brown egg as the game (`eggscape-art icon`, `make icon`), laid
  diagonally on the warm yolk gradient of the first, hand-drawn icon. The egg is drawn a little larger than in the game
  (0.8 instead of 0.62 bowl units) so it still reads at home-screen size. The launch screen color is the system's
  grouped background (light and dark), which the first tab shows.
- **Coins.** Single-player runs earn coins (`CoinRewards`); hot-seat turns earn none (several people share one
  phone and wallet); nearby races earn coins including the place bonus once the host announces the results.
- **Egg prices (owner, 2026-10-28).** Only the classic white egg is free; every other egg is locked until it is
  unlocked with coins. The owner asked for the brown egg to cost about one game and for the others to get
  exponentially harder. So the brown egg costs 55 coins, exactly what a clean 150 m time trial in calm weather pays,
  and every following egg in catalog order costs about 1.3 times the one before (each step between 1.25× and 1.35×),
  rounded to friendly numbers: 55, 70, 90, 120, 160, 200, 260, 350, 450, 600, 750, 1,000, 1,300, 1,700, 2,200,
  2,800, 3,600, 4,800 and 6,000 for the rainbow egg. 1.3 is the factor that turns 19 paid eggs into a ladder from one
  run to a long-term goal of about 110 short runs: the next egg is always a few runs away, while the last ones take
  hours of play or a coin pack. A factor of 1.5 would put the last egg above 80,000 coins, 1.15 below 700. All eggs
  together cost 26,505 coins, roughly seven hours of play. The tier bands (common 50–400, rare 450–2,000, epic
  2,200–4,000, legendary 4,500–7,500) follow the ladder. Testers who got the brown egg for free in earlier builds keep
  it, because wallets store it with the owned eggs.
- **Coin packs** stay at 600 / 2,000 / 5,000 coins for the suggested 0.99 / 2.99 / 5.99 €: the small pack buys any
  common egg, the medium one any rare egg, the large one any egg but the last, which takes the large pack plus about
  twenty runs. Bigger packs give more coins per euro (606, 669, 835). The "Bestes Angebot" badge goes to the pack
  with the most coins for the money at the prices StoreKit reports for the player's storefront, so it stays right
  if a storefront is priced differently.
- **Shop layout.** The shop stays one tab (the app keeps its four tabs) with two pages, "Eier" and "Münzen", picked
  with a segmented control. The page is kept in `AppNavigation`, so the coin balance, the "Münzen kaufen" button of
  the not-enough-coins alert and the screenshot staging can open the coin page. Locked eggs show their real look with
  a padlock in front of them rather than a silhouette, so players see what they save for: the padlock is filled with
  the accent color once the balance covers the price and frosted while it does not. Unlocking an egg also puts it on,
  as buying did before.
- **Game Center.** The player is signed in silently at launch (not in UI tests or screenshot mode), so scores reach
  the leaderboards right after a run and an accepted invitation opens the online room, also when it launched the app.
  Apple's sign-in sheet, if GameKit asks for one, waits until Bestenliste or Online opens instead of popping up over a
  run. Scores reached while signed out are submitted from the personal bests right after signing in. Time-trial
  leaderboards take the best time of any weather, because one board per weather option would split the few players.
- **MultipeerConnectivity warnings.** The deprecation warnings are silenced only inside `MultipeerTransport.swift` with
  `@diagnose(DeprecatedDeclaration, as: ignored)`, guarded by `#if hasAttribute(diagnose)` so older compilers (CI)
  still build it, just with warnings.
- **Nearby join data.** A joiner sends its player id, nickname and egg skin as the MultipeerConnectivity invitation
  context, so the message set of the spec needs no extra "hello" message.
- **Race time in multiplayer** is measured on the wall clock from the shared start, so a phone that was briefly in
  the background does not report a shorter time. The finish order is the arrival order at the host, as specified.
- **Screenshots** are staged scenes (`--screenshot-mode start|calibration|run-sunny|run-rain|run-storm|lobby|results|
  shop`) with ephemeral data and fixed seeds; the nearby lobby is a demo without networking. Camera mode cannot be
  captured in the Simulator, so the screenshots use the white background.
- **Localization.** German keys are the German text; where one German word needs two English translations, the key is
  semantic with a German default value (e.g. `pause.resume` = "Weiter" → "Resume", while "Weiter" → "Next").
  `make strings` fails if any UI string lacks an English translation.
